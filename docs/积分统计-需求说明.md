# 团队积分统计｜需求说明

## 1. 文档目的

本文档用于说明团队管理页“使用统计 / 积分统计”的页面范围、业务口径、交互状态、接口依赖和验收标准，供产品、设计、开发和测试共同使用。

## 2. 适用范围

### 2.1 本次包含

- 团队管理 > 使用统计 > 积分统计页面。
- 团队积分余额、周期消耗、新增积分和当日消耗概览。
- 积分消耗趋势图。
- 按时间范围、使用类型、成员或功能查询积分消耗明细。
- 当前筛选条件下的明细导出入口。
- 加载中、空数据、加载失败和无权限状态。
- 页面内独立“需求说明”入口及 AI 提示词复制能力。

### 2.2 本次不包含

- 积分购买、赠送、扣除规则配置和退款处理。
- 真实账单结算、财务对账和积分余额修改。
- 跨团队积分合并统计。
- 成员管理、团队切换和权限配置本身；这些能力沿用现有团队管理页面。

## 3. 背景与目标

团队账户概览当前只展示团队剩余积分，管理员无法判断积分在什么时间、由谁、通过什么功能被消耗，也不能对异常消耗进行复核。本需求提供独立的积分统计页面，让管理员先看整体余额和趋势，再通过筛选条件定位明细。

目标：

1. 管理员进入页面后能够立即看到当前剩余、本月消耗、本月新增和今日消耗四项指标。
2. 管理员能够按时间范围和使用类型查看每日消耗趋势。
3. 管理员能够通过成员或功能关键词定位明细，并导出当前筛选结果。
4. 空数据、失败和无权限状态不展示误导性数据，并提供明确的下一步操作。

## 4. 术语定义

| 术语 | 定义 |
| --- | --- |
| 当前剩余 | 当前团队积分账本中可用的剩余积分。 |
| 本月消耗 | 当前自然月已扣除的团队积分总量。 |
| 本月新增 | 当前自然月发放或购买到账的团队积分总量。 |
| 消耗明细 | 一次积分扣除对应的一条记录，包含时间、成员、功能、类型、扣除数量和扣除后余额。 |
| 使用类型 | 积分消耗所属业务分类：AI生成、设计功能、会员/活动。 |

## 5. 页面入口与权限

1. 首页底部导航点击“管理”，进入团队管理页面。
2. 点击左侧“使用统计”，主内容区切换为“积分统计”。
3. 当前团队为“北京艺源酷”时，只展示该团队的数据；切换团队后重新请求所选团队数据。
4. 团队管理员可以查看统计和导出明细；普通成员无团队统计权限，显示无权限状态，不返回其他团队数据。
5. 页面沿用现有团队管理顶部导航、左侧管理菜单和视觉样式。

## 6. 页面信息架构

```text
团队管理
└── 使用统计
    └── 积分统计
        ├── 指标概览
        ├── 使用类型 / 时间 / 成员筛选
        ├── 积分消耗趋势
        └── 积分消耗明细
```

## 7. 功能需求

### 7.1 指标概览

| 指标 | 默认展示 | 规则 |
| --- | ---: | --- |
| 当前剩余 | 369320 | 展示当前可用积分和“实时余额”说明；为 0 时展示 0。 |
| 本月消耗 | 42680 | 按当前自然月统计，并与明细筛选口径一致。 |
| 本月新增 | 120000 | 按当前自然月统计发放或购买到账积分；没有记录时为 0。 |
| 今日消耗 | 1260 | 按当前自然日统计，用于观察当天异常消耗。 |

示例数字仅用于当前原型验证，正式接入后由接口返回。

### 7.2 筛选工具栏

- 使用类型：全部、AI生成、设计功能、会员/活动。
- 时间范围：近7天、近30天、近90天、自定义；默认近30天。
- 成员/功能搜索：按成员昵称、用户 ID 或功能名称模糊匹配。
- 改变任一筛选条件后，趋势图和明细列表使用同一条件刷新，列表回到第 1 页。
- 自定义时间范围不得超过 90 天，开始日期不得晚于结束日期。
- “清空筛选”恢复全部类型、近30天和空关键词。

### 7.3 积分消耗趋势

- 按日聚合所选时间范围内的消耗积分。
- 纵轴单位为积分，横轴展示日期。
- 趋势图不要求显示百分比，鼠标悬停时显示日期和对应积分值。
- 无数据时显示“暂无积分消耗数据”，不渲染虚构曲线或默认零线。

### 7.4 积分消耗明细

列表字段如下：

| 字段 | 说明 |
| --- | --- |
| 消耗时间 | 精确到分钟，格式为 `YYYY-MM-DD HH:mm`。 |
| 使用成员 | 展示成员昵称及用户 ID。 |
| 使用功能 | 记录实际消耗积分的业务功能。 |
| 使用类型 | 使用类型标签。 |
| 消耗积分 | 以负数展示扣除数量。 |
| 消耗后余额 | 本次扣除完成后的团队余额。 |

其他规则：

- 默认按消耗时间倒序排列。
- 默认每页 10 条，支持分页。
- 当前原型提供导出入口；正式导出格式、单次最大条数和异步导出策略待后端确认。

## 8. 业务规则

1. 所有指标、趋势和明细必须限定在当前团队和当前筛选条件内。
2. 趋势聚合、余额计算和明细列表必须使用相同的团队 ID、时区和积分账本口径。
3. 积分数值按整数展示，不显示小数；接口为空时按业务字段规则展示 0 或空态。
4. 会员/活动类型可以记录积分赠送、购买到账等相关业务，但不得把新增积分误计入消耗趋势。
5. 无权限请求不得降级展示其他团队数据或本地缓存中的跨团队数据。
6. 筛选条件发生变化时，旧列表数据不能继续显示为新条件结果；加载中应显示加载状态。

## 9. 页面交互与状态

| 状态 | 页面表现 | 用户操作 |
| --- | --- | --- |
| 首次加载 | 指标、趋势和列表区域显示加载中状态。 | 等待请求完成。 |
| 加载成功 | 展示指标、趋势和明细。 | 继续筛选、分页或导出。 |
| 空数据 | 趋势和列表显示“暂无积分消耗数据”，保留清空筛选。 | 调整时间、类型或关键词。 |
| 加载失败 | 显示“积分统计加载失败，请重试”。 | 点击重试，保留当前筛选条件。 |
| 无权限 | 显示权限说明，不展示统计数据。 | 返回账户概览或联系团队管理员。 |
| 导出中 | 导出按钮进入处理中，避免重复提交。 | 等待完成或收到失败提示。 |
| 导出失败 | 显示导出失败提示，不生成空文件。 | 重试导出。 |

## 10. 数据与接口依赖

接口名称和字段待后端确认，建议至少拆分为以下能力：

### 10.1 团队积分概览

请求参数建议包含：`teamId`、`timezone`、`range`。

返回字段建议包含：`remainingPoints`、`monthConsumed`、`monthAdded`、`todayConsumed`、`updatedAt`。

### 10.2 积分消耗趋势

请求参数建议包含：`teamId`、`startDate`、`endDate`、`usageType`、`timezone`。

返回字段建议包含：`date`、`consumedPoints`。

### 10.3 积分消耗明细

请求参数建议包含：`teamId`、`startDate`、`endDate`、`usageType`、`keyword`、`page`、`pageSize`。

返回字段建议包含：`consumedAt`、`memberName`、`memberId`、`featureName`、`usageType`、`points`、`balanceAfter`、`total`。

### 10.4 导出明细

导出请求必须携带当前页面全部筛选条件。导出格式、最大条数、同步/异步方式和权限校验由后端确认。

## 11. 埋点与日志

| 事件 | 触发时机 | 建议参数 |
| --- | --- | --- |
| `team_credit_statistics_view` | 进入积分统计页并完成首屏加载 | `teamId`、`role`、`loadStatus` |
| `team_credit_statistics_filter` | 改变类型、时间或关键词 | `teamId`、`usageType`、`range`、`keyword` |
| `team_credit_statistics_export` | 点击导出 | `teamId`、筛选条件、结果条数 |
| `team_credit_statistics_retry` | 点击重试 | `teamId`、失败接口 |

日志不得记录敏感凭证；导出失败需记录失败原因和请求追踪 ID。

## 12. 验收标准

- [ ] 从“管理 > 使用统计”进入后，标题为“积分统计”，侧边栏正确高亮“使用统计”。
- [ ] 首屏展示四项指标，数值格式统一，0 值不显示为空。
- [ ] 时间范围支持近7天、近30天、近90天和自定义，默认近30天。
- [ ] 使用类型和成员/功能关键词能够同时作用于趋势和明细。
- [ ] 趋势图按日展示积分消耗，空数据时展示空态。
- [ ] 明细展示时间、成员、功能、类型、消耗积分和余额，并按时间倒序。
- [ ] 筛选变化后列表回到第 1 页，清空筛选恢复默认状态。
- [ ] 导出入口携带当前筛选条件；原型未接真实接口时必须给出明确演示提示。
- [ ] 加载失败、无权限、空数据和导出失败均有明确文案和下一步操作。
- [ ] “需求说明”入口可打开本文档对应的结构化说明，并支持复制 AI 提示词。

## 13. 测试用例

1. 管理员进入页面，校验页面标题、侧边栏高亮和四项指标。
2. 依次切换四种使用类型，校验趋势图和明细列表同步更新。
3. 依次切换三种预设时间范围，校验请求参数和列表分页重置。
4. 输入成员昵称、用户 ID、功能名称和不存在的关键词，校验匹配结果与空态。
5. 点击清空筛选，校验筛选项、趋势和列表恢复默认值。
6. 在无数据、接口失败、无权限和导出失败场景下校验提示文案和操作按钮。
7. 使用普通成员身份访问，校验不会返回其他团队数据。
8. 打开需求说明并复制 AI 提示词，校验文档包含背景、目标、功能、交互和验收标准。

## 14. 待确认事项

1. 原型中积分统计接口的真实字段名、接口拆分方式和数据更新时间待后端确认。
2. 团队积分是否按北京时间统计，及跨时区团队的展示时区待产品确认。
3. 余额字段是实时余额还是按日结算余额待财务/积分服务确认。
4. 自定义时间范围的最大跨度、最早可查询日期和历史数据保留周期待后端确认。
5. 导出文件格式、单次最大条数、同步/异步导出和权限范围待后端确认。
6. 积分赠送、购买到账和退款回退是否需要单独的“积分变动明细”页待产品确认。
